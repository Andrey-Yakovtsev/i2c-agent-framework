---
name: i2c-code
description: Implements an RFC component or adds a feature to already-generated code
---
Реализовать код через конвейер coding-агентов. Два режима:

- `--rfc N` — реализовать компонент по RFC-N с нуля (Implementation Plan →
  Docker-окружение → coding + test-writer параллельно → тесты → верификация AC).
- `--feature N "описание"` — добавить новую фичу в **уже сгенерированный** код
  RFC-N. Architect синтезирует AC из описания, coding-агенты расширяют
  существующий IMPL, тесты только для новых AC. Крупную/архитектурную фичу
  Supervisor завернёт с предложением сделать ADR/RFC.

Голый номер без флага трактуется как `--rfc`. Флаг `--auto` (любой режим)
отключает запросы подтверждений — агенты работают автономно.

**Аргумент:** `--rfc N` либо `--feature N "описание"`, опционально `--auto`.
**Примеры:**
- `/i2c-code --rfc 3` или `/i2c-code 3`
- `/i2c-code --rfc 3 --auto`
- `/i2c-code --feature 3 "тёмная тема в настройках"`
- `/i2c-code --feature 3 "экспорт в CSV" --auto`

Если `$ARGUMENTS` пуст — спроси пользователя: "Что реализовать? Укажи
'--rfc N' для реализации RFC с нуля или '--feature N \"описание\"' для
добавления фичи в существующий код (опционально --auto):"
Дождись ответа и используй его как аргумент.

Прочитай файл {{FRAMEWORK_DIR}}/orchestrator.md (используй Read tool) и выполни команду `code $ARGUMENTS` по инструкциям из этого файла.
